Start with what you would do by hand

Three runners, 1, 2 and 3, finish a race. List every possible finishing order. By hand: 123, 132, 213, 231, 312, 321. Six orders. You likely did it by fixing who came first, then who came second among the rest. Count it that way: 3 choices for first, then 2 for second, then 1 left:

3 × 2 × 1 = 6, and n × (n − 1) × … × 1, called n factorial, in general

With five runners that is 120 orders and the by-hand method starts to slip; with eight, 40,320. The pattern is the "fix first, then the rest" idea written so a computer never repeats and never forgets.

Build the structure, one piece at a time

Piece one: a path, the order built so far, a stack you push onto and pop from.

Piece two: a used array, one yes/no per runner, saying whether that runner is already in the path. Without it you would have to scan the path every time to see who is still free.

Piece three: the rule, solve(): if the path has all n runners, record a copy. Otherwise, for each runner r with used[r] = no, in order: mark used[r] = yes, push r, call solve(), pop r, mark used[r] = no. Then move to the next r.

Each level of the recursion decides one position in the order; the recursion tree has n branches at the top, n − 1 below, and so on down to n factorial leaves.

Why it is correct

The invariant: used[r] is yes exactly when r is in the path. Both are changed together, mark-and-push on the way down, pop-and-unmark on the way up, so it never breaks. Because of it, each level picks only runners not already placed, so a recorded path is a genuine order with no repeats. Because the loop tries every free runner at every level in a fixed order, every order is produced, and produced once: two different orders differ at some first position, and the loop at that level tries the two runners in separate branches.

Why it is fast

The leaves number n factorial, and each leaf copies a path of length n:

work ≈ n × n factorial

The used array makes each "is this runner free?" check constant time instead of a scan of the path, which would add another factor of n.

How to recognise it in an interview

Cues: "all orderings", "all arrangements", "every permutation", or a small n (up to about 9) where items must be placed one per position. The first thing to say: "I will backtrack with a used array, choosing any unused element for the next position." Permutations is the example above. Permutations II has repeated values: sort, and at each level skip a value equal to the previous one if that previous copy is currently unused, so equal runners are placed in one canonical order. Letter Combinations of a Phone Number is the same loop shape with one position per digit and the digit's letters as the choices.
