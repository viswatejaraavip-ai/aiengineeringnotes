Start with what you would do by hand

You have four raffle tickets with weights 1, 3, 2 and 4, and you want to draw one so that the ticket with weight 4 is four times as likely as the ticket with weight 1. By hand you would write the first ticket on 1 slip of paper, the second on 3 slips, the third on 2 and the fourth on 4, put all 10 slips in a hat, and draw one. That is correct. It is also wasteful: if the weights were 1 and 999,999 you would be writing a million slips.

Build the structure, one piece at a time

Instead of slips, lay the weights end to end on a number line. Ticket 0 owns the range 1, ticket 1 owns 2 to 4, ticket 2 owns 5 to 6, ticket 3 owns 7 to 10. The right edges of those ranges are the running totals, called prefix sums:

Now draw a single random integer r from 1 to 10 and find which ticket owns it: the first ticket whose prefix is at least r. Because the prefix column is sorted, that lookup is a binary search. Draw r = 7: the middle prefix 4 is below 7, so look right; prefix 6 is below 7, look right; prefix 10 is the first one at or above 7, so ticket 3 wins. Draw r = 4: prefix 4 is the first one at or above 4, ticket 1 wins.

The second tool in this family handles the opposite situation, where you do not know how many items there are because they arrive one at a time and cannot be stored. Reservoir sampling keeps one chosen item. When item number i arrives, replace the chosen item with it with probability 1/i. One variable and a coin flip per item.

Why it is correct

For the weighted pick, ticket k owns exactly wk of the integers 1 … W, where W is the total, and each integer is equally likely, so

P(ticket k) = wk / W

which is the definition of a weighted draw. The binary search is correct because prefixes are non-decreasing, so "first prefix ≥ r" is a boundary with everything false on the left and true on the right.

For the reservoir, the invariant is that after i items each of them is the chosen one with probability 1/i. It is true for i = 1. When item i + 1 arrives it is chosen with probability 1/(i + 1). Any earlier item was chosen with probability 1/i and survives the new coin flip with probability i/(i + 1), so its chance is (1/i) · (i/(i + 1)) = 1/(i + 1), the same as the newcomer's. The invariant holds for every i, including the final count.

Why it is fast

Building the prefix table is one pass, O(n), done once. Each pick is a binary search over n prefixes, O(log n), and uses O(1) random numbers. The slips-in-a-hat method needed O(W) memory, and W can be astronomically larger than n. Reservoir sampling is O(1) memory and O(1) work per item, which is the best possible when the items cannot be stored.

How to recognise it in an interview

Cues: "pick an index with probability proportional to", "random node of a linked list in one pass", "shuffle", "random point inside these rectangles", or "the stream is too large to store". Say: "weighted means prefix sums plus a binary search; unknown length means reservoir sampling".

Random Pick with Weight is the table above exactly. Linked List Random Node is the reservoir: walk the list once, keeping each node with probability 1/i. Random Point in Non-overlapping Rectangles is the weighted pick where each rectangle's weight is its number of integer points, followed by a uniform point inside the chosen rectangle.
