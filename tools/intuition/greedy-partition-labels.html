Start with what you would do by hand

Cut the string ababcbacadefegde into as many pieces as possible so that no letter appears in two different pieces. By hand you would start a piece at the first a, notice that a appears again later, scan forward to its last appearance, notice that the piece now contains b and c, check where those last appear, and so on. It works, but every time a new letter enters the piece you rescan the string to find its last position, and with a long string of many letters that is a lot of rescanning: O(n) per letter, up to O(n × 26) checks for each piece and more in careless versions.

Build the structure, one piece at a time

The first piece of structure is a tiny table: for each letter, the index of its last occurrence. One pass over the string fills it, overwriting as it goes. For our string: a → 8, b → 5, c → 7, d → 14, e → 15, f → 11, g → 13.

The second piece is one number, end: the furthest index the current piece must stretch to. Walk the string a second time. At each index i, set end = max(end, last[s[i]]). When i catches up with end, the piece can close here: every letter inside it has its last occurrence at or before end.

Why it is correct

The invariant: while scanning the current piece, end is the maximum last-occurrence of every letter seen in the piece so far. A piece cannot close before end, because some letter in it reappears at end. When i reaches end, every letter in the piece has its last occurrence at or before i (that is what the maximum says), so none of them appears later, and closing here is legal. Closing as early as legal makes the most pieces: any cut earlier than this one would split some letter, and delaying the cut only merges pieces that could have been separate.

end = max over j ≤ i in the piece of last[s[j]]; close when i = end

Why it is fast

Two passes over the string, each doing constant work per character, plus a table of 26 integers: O(n) time and O(1) extra memory. The precomputed table is what removes the rescanning; "where does this letter last appear" becomes a lookup.

How to recognise it in an interview

Cues: "partition into as many parts as possible", "each letter in at most one part", or intervals defined by first and last occurrence. Say: I will precompute each element's last position, then sweep with a running furthest-reach and cut when the index meets it. Partition Labels is the example. Max Chunks To Make Sorted is the same sweep where the reach is the maximum value seen so far compared with the index. Merge Intervals uses the identical "extend the current end, close when passed" motion over sorted intervals.
