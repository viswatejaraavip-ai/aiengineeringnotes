Start with what you would do by hand

A binary search tree (BST) has one rule: for every node, everything in its left subtree is smaller than it, and everything in its right subtree is larger. Check this tree: 5 at the top; 1 on its left; 4 on its right; 3 and 6 under 4. Is it a BST?

A quick glance at each parent and its two children says yes: 1 < 5, 4 < 5... wait, 4 is on the right of 5 and 4 < 5. Already broken. But suppose the right child had been 7 with 3 and 8 under it. Then every parent-child pair looks fine (3 < 7 < 8, 1 < 5 < 7), yet 3 sits in the right subtree of 5 while being smaller than 5. The rule is about every ancestor, not just the parent. Checking each node against all its ancestors by hand costs up to h comparisons per node, roughly n × h in total.

Build the structure, one piece at a time

Piece one: an allowed range for every node, two numbers (low, high). The root may be anything: (−∞, +∞).

Piece two: how the range changes when you step down. Going to the left child, every value there must be smaller than the current node, so the high end becomes the current value. Going right, the low end becomes the current value. The range is handed down along with the recursion, exactly like the state in root-to-leaf problems.

Piece three: the check. At each node, test low < value < high. If it fails anywhere, the tree is not a BST. If it passes everywhere, it is.

NodeRange receivedInside?Left child getsRight child gets
5(−∞, ∞)yes(−∞, 5)(5, ∞)
1(−∞, 5)yes(−∞, 1)(1, 5)
4(5, ∞)no: 4 is not above 5stop, not a BST

In the second tree (7 on the right with 3 under it), 7 receives (5, ∞), passes, and hands 3 the range (5, 7). 3 is not inside, so the deep violation is caught too, without ever looking back at the ancestors.

Why it is correct

The invariant: the range handed to a node is exactly the set of values that all of its ancestors together allow. At the root no ancestor exists, so the range is everything. Stepping to a left child adds one constraint, "smaller than me", which intersects the old range with (−∞, value); stepping right intersects with (value, ∞). Intersecting intervals is what the two updates do.

range(v) = intersection over ancestors a of { (−∞, a) if v is left of a, (a, ∞) if right of a }

So "value inside its range" means "value satisfies every ancestor", which is the BST rule for that node. Checking it at every node checks the whole rule. Use strict inequalities so duplicate values are rejected, as the problems require.

Why it is fast

Each node receives two numbers and does two comparisons: O(n) time, O(h) stack. The by-hand method compared every node with every ancestor, O(n × h), which for a deep tree is close to n2. Carrying the bounds compresses all the ancestors into two numbers.

How to recognise it in an interview

"Is this a valid BST", "sum of all values between L and R in a BST", "trim the BST to a range", "count subtrees whose values fit a bound". Say: "I will pass an allowed (low, high) range down the recursion, tightening one side at each step." Validate Binary Search Tree is this exactly, and the classic trap is checking only parent and child. Range Sum of BST uses the bounds the other way: because the tree is valid, a node below L has nothing useful on its left, so skip that side. Trim a Binary Search Tree cuts off a subtree the moment its root falls outside the range.
