Start with what you would do by hand

Take the list 6, 0, 8, 2, 1, 5. A "ramp" is a pair of positions i < j with nums[i] ≤ nums[j], and its width is j − i. We want the widest ramp. Here the best is position 1 (value 0) to position 5 (value 5), width 4.

By hand you would check every pair: 15 pairs for 6 numbers, n(n − 1)/2 in general, which is 50 million pairs for ten thousand numbers. Most of those pairs are pointless. A left end at position 3 (value 2) can never beat a left end at position 1 (value 0): position 1 is further left and smaller, so any j that works for 3 works for 1 with a bigger width.

So the only left ends worth keeping are the ones that are smaller than everything before them. Here that is 6 (position 0) and 0 (position 1). Everything after 0 is bigger than 0, so it is a worse left end.

Build the structure, one piece at a time

Piece 1: a stack of candidate left ends. Walk left to right. Push a position only if its value is smaller than the value on top of the pile. The pile then holds positions with strictly decreasing values: 0(6), 1(0) in the example. The other four positions are never pushed.

Piece 2: scan right ends from the far right. Now walk j from the last position backwards. For each j, while the top of the pile has a value ≤ nums[j], that top is a valid left end for this j: record the width j − top and pop it.

Why pop? Because j is the rightmost right end we will ever try for that left end (we are moving leftwards), so no wider ramp with that left end can appear later.

The widest ramp recorded is 4. This two-pass trick, where the stack gives each element one boundary when pushed and the other when popped, is the general shape of the pattern: one pass can find both the previous smaller and the next smaller element of every position.

Why it is correct

The invariant has two halves. After pass 1 the pile holds every position that is a new minimum so far, in decreasing order of value. During pass 2, every position still on the pile has not yet found any right end, and every popped position was matched with the largest j that works for it.

For the first half: a position that is not a new minimum has an earlier, smaller position, which dominates it as a left end, so dropping it loses nothing. For the second half: when j pops the top i, every larger j′ > j was already tried and did not pop i, meaning nums[j′] < nums[i], so j is the furthest right end for i and j − i is the best width with left end i. Taking the maximum over all popped pairs gives the answer.

The same reasoning gives, for the "previous and next smaller" version: when j pops i, nothing between them was smaller than i (it would have popped i), so j is the next smaller, and the element below i on the pile is the previous smaller.

Why it is fast

Pass 1 touches each position once. In pass 2 each position on the pile is popped at most once, and j moves n steps.

work ≤ n (pass 1) + n (moves of j) + n (pops) = 3n, which is O(n)

For ten thousand numbers that is thirty thousand steps instead of fifty million pairs.

How to recognise it in an interview

The cues are "for each element, the nearest smaller (or greater) on both sides", "widest pair with a condition", or a sum where each element contributes according to how far it can extend left and right. Say: "A monotonic stack gives each element its left boundary at push time and its right boundary at pop time, so one pass finds both."

Maximum Width Ramp is the example above. Sum of Subarray Minimums uses the left and right boundaries to count how many subarrays each element is the minimum of, then multiplies. Shortest Unsorted Continuous Subarray uses the same stack to find the first and last position that is out of order.
