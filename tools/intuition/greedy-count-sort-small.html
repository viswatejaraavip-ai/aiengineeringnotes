Start with what you would do by hand

From the letters of abccccdd, using each letter at most as many times as it appears, build the longest palindrome you can. By hand you would start arranging letters: dccaccd reads the same backwards and uses 7 letters. Is 8 possible? You would try moving letters around, and it is not obvious when to stop. For a string of 2,000 letters, arranging by trial is hopeless: there are more arrangements than atoms in the universe.

Build the structure, one piece at a time

The key realisation is that the order of the input letters does not matter at all, only how many of each there are. So the first and only structure is a count table, 26 slots for lowercase and 26 for uppercase, filled by one pass over the string: a → 1, b → 1, c → 4, d → 2.

Now build the answer from the counts, not from the string. A palindrome pairs every letter with its mirror image, except possibly one letter in the exact middle. So each letter contributes its count rounded down to an even number, and if any letter has a count left over, one single letter can sit in the middle.

  1. a × 1: 0 pairs, contributes 0; one a left over.
  2. b × 1: 0 pairs, contributes 0; one b left over.
  3. c × 4: 2 pairs, contributes 4.
  4. d × 2: 1 pair, contributes 2.
  5. Leftovers exist, so add 1 for the middle. Total 0 + 0 + 4 + 2 + 1 = 7.

The length is 7, and one such palindrome is dccaccd. The algorithm never wrote the palindrome down; it only counted.

Why it is correct

A palindrome of length m has positions k and m − 1 − k holding the same letter, so every letter except the centre (when m is odd) appears an even number of times. Therefore no palindrome can use more than an even number of copies of each letter, plus at most one extra letter in total. That gives an upper bound: the sum of the counts rounded down to even, plus 1 if any count is odd. The construction above reaches that bound: place each pair symmetrically and one leftover in the middle. Upper bound met, so it is the maximum.

length = Σletters 2·⌊count/2⌋ + [some count is odd]

Why it is fast

One pass to count is O(n), and the construction loops over at most 52 slots, which is constant: O(n) time, O(1) memory. For 2,000 letters that is about 2,050 steps. Every trial-and-arrangement method is exponential, because it treats the order as information when the order is irrelevant.

How to recognise it in an interview

Cues: a small fixed alphabet (letters, digits, task types), and a question that would be unchanged if the input were shuffled. Say: the order does not matter, so I will count first and reason about the counts. Longest Palindrome is the example. Reorganize String checks that the most frequent letter is at most half the length (rounded up) and then interleaves from the counts. Task Scheduler has the closed form (f − 1)(n + 1) + (number of tasks with the top count), where f is the highest count, again purely from the count table.
