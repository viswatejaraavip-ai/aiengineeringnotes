Start with what you would do by hand

Coins of value 2, 3, 6 and 7, as many of each as you like. Which multisets of coins add up to 7? By hand: 2+2+3 and 7. Easy for a target of 7. Now imagine listing all ways to make 30 with those coins. You would soon write 2+2+3+... and later 3+2+2+..., the same bag of coins in a different order, and have to cross one out. Avoiding those duplicates by checking every new answer against the old ones is slow and error prone.

Build the structure, one piece at a time

Piece one: sort the coins: [2, 3, 6, 7]. Piece two: a path, the coins chosen so far, as a stack. Piece three: remaining, the target minus the path's sum.

Piece four, the rule that kills duplicates: a start index. When you are choosing the next coin, you may choose only coins at position start or later. If you chose the coin at position p, the next choice starts at p again, not p + 1, because reuse is allowed, but never earlier. That forces every path to be written in non-decreasing order, so 2+2+3 can appear but 3+2+2 cannot.

Piece five: pruning. Because the coins are sorted, once a coin is bigger than remaining, every later coin is too, so stop the loop.

Why it is correct

The invariant: the path is always sorted, because each new coin comes from the current start or later and start never moves backwards. Every multiset of coins has exactly one sorted spelling, so each answer is recorded exactly once. Nothing is lost: any valid multiset, written in sorted order, is one of the paths the loop builds, since at each step its next coin is at or after the position of the previous one. Pruning is safe because remaining only shrinks along a path, so a coin too big now is too big for every deeper step too.

Why it is fast

Without the start index, a combination of k coins would be generated up to k factorial times (every ordering of its coins). With it, each of the C combinations is built once, costing about its length to copy:

work ≈ k · C plus the dead branches that pruning cuts short

The dead branches are bounded by the number of sorted prefixes whose sum stays under the target, which for small targets is tiny.

How to recognise it in an interview

Cues: "all combinations that sum to", "choose k of n", "may reuse" or "each once", "no duplicate combinations". The first thing to say: "backtrack with a start index so every combination is built in sorted order once." Combination Sum is the example above with reuse, so the recursive start is p. Combination Sum II forbids reuse and has duplicate coins: recurse with p + 1 and, within a level, skip a coin equal to the previous coin. Combinations is the same loop with the sum replaced by a count of k picks.
