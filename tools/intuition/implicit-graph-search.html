Start with what you would do by hand

A padlock has two wheels, each showing a digit 0 to 9, and starts at 00. One move turns one wheel up or down by one, and wheels wrap, so 0 goes down to 9. Some combinations are dead ends that jam the lock: say 10 and 01. What is the fewest moves to reach 99? By hand: 00 → 90 → 99, two moves, going "down" twice. You found it by thinking of the combinations you could reach in one move, then two.

That is breadth-first search. The difference from a usual graph problem is that nobody gave you a list of nodes and edges. There are 100 combinations and 400 possible moves, and for a 4-wheel lock 10,000 combinations and 80,000 moves. Writing them all down first would waste time and memory on states you never visit.

Build the structure, one piece at a time

Piece one: decide what a state is. Here, the string of digits on the wheels, such as "00". A state is a node.

Piece two: a rule that produces neighbours on demand instead of a stored list: for each wheel, make two copies of the state, one with that digit +1 and one with −1, wrapping 9 and 0. From "00" the rule gives 10, 90, 01, 09. That rule is the whole edge list; it just has not been written out.

Piece three: ordinary BFS with a queue and a visited set, plus a dead-end set to refuse.

steptook out (moves)generatedqueue after
100 (0)10 dead, 90, 01 dead, 09[90, 09]
290 (1)00 seen, 80, 91, 99[09, 80, 91, 99]
…99 was generated with 2 moves; the first time it is seen is the shortest route

Why it is correct

BFS takes states out of the queue in order of the number of moves used to reach them: all 0-move states, then 1-move, then 2-move. So the first time the target is generated, no shorter route exists; a shorter route would have generated it in an earlier layer. The visited set stops the search from going round in circles, which matters because wheels wrap. The neighbour rule must produce exactly the legal moves, no more and no fewer, and that is the only place the problem's details enter.

Why it is fast

Each state is visited at most once, and each visit runs the rule once, producing a fixed number of neighbours b. For w wheels:

states = 10w, work ≈ 10w · 2w

For four wheels that is about 80,000 steps. Trying move sequences without a visited set would be 8 to the power of the path length, with no bound at all.

How to recognise it in an interview

Cues: "fewest operations to transform X into Y", "each step changes one letter / one digit / one unit", "minimum moves", with no graph given. The first thing to say: "the states form a graph I never need to store; I will BFS with a function that generates neighbours." Open the Lock is the example above. Word Ladder is the same with words as states and "change one letter to make another dictionary word" as the rule. Minimum Genetic Mutation is Word Ladder with an alphabet of four letters.
