Start with what you would do by hand

You are given five points on a grid: (1,1), (1,3), (3,1), (3,3) and (4,1), and asked for the smallest rectangle, with sides parallel to the axes, whose four corners are all among the points. By hand you would try to spot four points that line up: (1,1), (1,3), (3,1), (3,3) do, with area 2 × 2 = 4. For five points your eye finds it. For 500 points you cannot, and the obvious program that tries every group of four points does 500 · 499 · 498 · 497 / 24, about 2.6 billion, checks.

Build the structure, one piece at a time

The first piece is a hash set of the points, so that "is (3,3) one of the given points?" costs one lookup instead of a scan. Put all five points in.

The second piece is an observation that cuts the work: a rectangle with axis-parallel sides is fixed by one diagonal. If (x1, y1) and (x2, y2) are opposite corners, the other two corners must be (x1, y2) and (x2, y1). So instead of choosing four points, choose two and ask the set whether the other two exist. Running through the pairs:

  1. (1,1) and (3,3): different x and different y, so a real diagonal. Corners (1,3) and (3,1): both in the set. Area |3 − 1| · |3 − 1| = 4. Best so far 4.
  2. (1,1) and (1,3): same x, so this is a side, not a diagonal. Skip.
  3. (1,3) and (4,1): corners (1,1) and (4,3). (4,3) is missing. Skip.
  4. (3,1) and (4,1): same y. Skip.
  5. Every other pair is a side or has a missing corner. Answer 4.

Other point problems use the same two ideas with a different key. Max Points on a Line hashes the direction between pairs; the direction (dx, dy) is divided by its gcd and given a fixed sign so that (2,4), (1,2) and (−1,−2) all become the same key (1,2). Number of Boomerangs hashes squared distances from each centre. K Closest Points needs no hashing at all, just squared distances and a heap or sort.

Why it is correct

Every axis-parallel rectangle among the points has two diagonals, and each diagonal is a pair of points with different x and different y. The loop visits every pair, so it visits both diagonals of every rectangle, and for each it checks exactly the two points that would complete it. A rectangle is counted when its corners exist and skipped otherwise, so the minimum found is the true minimum. Keeping the smaller area as you go is safe because the area of a candidate does not depend on the order of discovery.

For the direction key, the invariant is that two pairs get the same key exactly when they point along the same line through the centre point. Dividing by the gcd removes scale, and fixing the sign removes orientation, so (1,2) and (−1,−2) collapse together, which is what "same line" means.

Why it is fast

There are n(n − 1)/2 pairs. For each pair the set answers two membership questions in expected O(1), so the whole run is O(n2). For 500 points that is about 125,000 pair checks, against 2.6 billion for choosing four points. Direction hashing is the same shape: for each centre, O(n) keys into a map, O(n2) overall.

pairs = n(n − 1)/2, quadruples = n(n − 1)(n − 2)(n − 3)/24

How to recognise it in an interview

Cues: a list of points on a plane, "rectangle", "square", "collinear", "on the same line", "equidistant", "closest to the origin". Say: "I will put the points in a hash set and iterate over pairs, deriving the remaining geometry from each pair, so the cost is quadratic rather than quartic".
