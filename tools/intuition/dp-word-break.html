Start with what you would do by hand

You are given the letters leetcode and a small dictionary, leet and code, and asked whether the string can be cut into dictionary words with nothing left over. By hand you would try a first cut: is l a word? No. le? No. lee? No. leet? Yes, so now solve the rest, code, the same way.

That looks harmless, but the "solve the rest" part can repeat itself. Imagine the dictionary a, aa, aaa and the string aaaaaaaab. The first cut can be after 1, 2 or 3 letters; each of those leaves a string that can again be cut three ways. The number of attempts grows like 3 × 3 × 3 × … and for 30 letters it is in the billions, and every attempt eventually hits the b and fails. Worse, most attempts re-solve the same leftover: "can aaaab be cut?" is asked thousands of times.

Build the structure, one piece at a time

The repeated question has only n + 1 different forms: can the first i letters be cut cleanly, for i from 0 to n. So keep one answer per prefix in an array dp of n + 1 cells. Start with everything unknown except dp[0], which is true: the empty prefix needs no words.

Fill the cells left to right. To decide dp[i], look at every earlier position j that is already true and ask whether the letters between j and i form a dictionary word. One yes is enough.

0(empty)by definitiontrue

4leetj = 0: leet is a wordtrue
5leetcj = 4: c is not a wordfalse
8leetcodej = 4: code is a wordtrue

The last cell, dp[8], is true, so the whole string can be cut: leet + code. Notice the structure is just an array of yes/no answers, filled once, and each new answer is built only from earlier answers.

Why it is correct

The invariant: dp[i] is true exactly when the first i letters can be split into dictionary words. Suppose it holds for every index below i. Any valid split of the first i letters has a last word; say it starts at j. Then the letters before j are also validly split, so dp[j] is true, and s[j:i] is a word. Our loop checks exactly that pair, so it finds the split. In the other direction, if the loop sets dp[i] true, it has a true dp[j] plus one more word, which is a valid split. So the invariant survives each step, and dp[n] answers the question.

dp[i] = OR over j < i of ( dp[j] and s[j:i] ∈ dictionary )

Why it is fast

There are n cells. Cell i looks back at up to i earlier cells, so the total number of (j, i) pairs is 1 + 2 + … + n = n(n+1)/2, which is O(n2). Each pair costs one dictionary lookup, constant time with a hash set (or O(word length) with a trie). For 30 letters that is about 465 lookups instead of billions of attempts. The only memory is the n + 1 booleans. A small extra: if the longest dictionary word has L letters, j only needs to go back L positions, giving O(n · L).

How to recognise it in an interview

Cues: "can the string be split into", "segment", "decode", "how many ways to break". Any time a prefix's answer depends only on shorter prefixes plus a last piece, this array is the tool. Say: I will keep one answer per prefix and build each from earlier prefixes. Word Break is this exactly. Word Break II stores, for each prefix, the list of splits instead of a boolean. Decode Ways is the same loop where the "words" are one- or two-digit codes and the cells hold counts instead of true or false.
