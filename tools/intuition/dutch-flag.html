Start with what you would do by hand

The array 2, 0, 2, 1, 1, 0 holds only the values 0, 1 and 2, and you must sort it in place, in one pass. By hand the easy way is to count: two 0s, two 1s, two 2s, then overwrite the array as 0, 0, 1, 1, 2, 2. That is two passes and it works only because the values are tiny labels; it does not generalise to "put everything smaller than a pivot on the left", where you cannot just rewrite the values.

So the real question is: how do you arrange three categories in one sweep, swapping elements rather than counting them?

Build the structure, one piece at a time

Picture the array as four zones, left to right: the 0s, the 1s, the unknown, and the 2s. Three indices mark the borders: lo is the first slot after the 0s, mid is the first unknown slot, hi is the last unknown slot. At the start everything is unknown: lo = mid = 0 and hi = n − 1.

Each step looks at the one element at mid and files it:

  • It is a 0: swap it with the slot at lo, which pushes it into the 0 zone and brings a 1 (or itself) to mid. Advance both lo and mid.
  • It is a 1: it is already in place at the end of the 1 zone. Advance mid.
  • It is a 2: swap it with the slot at hi, which pushes it into the 2 zone. Move hi left, but do not advance mid, because the element that just arrived from hi is still unknown.

Why it is correct

The invariant, kept true after every step: slots 0 … lo − 1 are 0s, slots lo … mid − 1 are 1s, slots hi + 1 … n − 1 are 2s, and slots mid … hi are unknown. At the start the three known zones are empty, so it holds. Check each case. A 0 at mid swaps with slot lo; that slot held a 1 if the 1 zone is non-empty (or the 0 itself if it is empty), so after the swap the 0 zone grows by one and the 1 zone shifts right by one, still all 1s. A 1 at mid extends the 1 zone by one. A 2 at mid swaps with slot hi, growing the 2 zone by one, and the unknown zone shrinks from the right. The loop ends when mid passes hi, so the unknown zone is empty and the array is 0s, then 1s, then 2s.

Why it is fast

Every step either advances mid or moves hi left, so the unknown zone, which starts at size n, shrinks by one each time. Hence at most n steps, each with at most one swap:

≤ n comparisons and ≤ n swaps: O(n) time, O(1) space

It is one pass, unlike counting, and it never looks at an element after it has been filed.

How to recognise it in an interview

Cues: "three kinds of values", "sort colours", "put values less than, equal to, and greater than the pivot in order", "one pass, constant space". Two kinds of values is the simpler two-pointer partition; three is this.

Say: "I will keep three zones with low, mid and high pointers and file the element at mid into the right zone with a swap." Sort Colors is the example. Partition Array According to Given Pivot is the same three zones with "less than", "equal to" and "greater than" the pivot, though that problem also asks to keep the relative order inside each zone, which needs a stable variant. Sort Array By Parity is the two-zone cousin.
