Start with what you would do by hand

In a family tree the lowest common ancestor (LCA) of two people is the nearest person who is an ancestor of both. Take the tree with 3 at the top; 5 and 1 below it; 6 and 2 under 5; 0 and 8 under 1. The LCA of 6 and 2 is 5, because both sit under 5 and 5 is lower than 3.

By hand you would write the path from the root to 6 (3, 5, 6) and the path to 2 (3, 5, 2), then read the last node they share: 5. That needs two searches to find the paths, each possibly visiting the whole tree, and a comparison of the two lists. It works, and it is already linear, but it stores paths and makes two passes. The pattern below does it in one pass with nothing stored.

Build the structure, one piece at a time

Piece one: give every node a question to answer about its own subtree: "do you contain p or q?" The answer is not yes or no; it is a node. A subtree that contains neither returns nothing (null). A subtree that contains exactly one of them returns that node. A subtree that contains both returns their LCA.

Piece two: the shortcut. If a node is itself p or q, return the node at once without looking below it. Either the other target is below it, in which case this node is the LCA anyway, or it is elsewhere, in which case this node is the one thing to report upward.

Piece three: a node that is neither asks its left child and its right child. If both come back with something, the two targets are on different sides, so this node is the LCA: return it. If only one side reports, pass that report up unchanged. If neither does, pass up null.

Why it is correct

The invariant: a non-null return from a subtree means that subtree contains at least one of the targets, and if it contains both, the returned node is their LCA. Check the three cases. A target node returns itself, which is correct for both readings. A node with reports from both sides contains both targets, on different sides, so nothing lower can be an ancestor of both, and this node is: it returns itself, the LCA. A node with one report contains exactly what that side contains, so forwarding the report keeps the statement true.

At the root the subtree is the whole tree, which contains both targets, so the root's return is the LCA. If a problem guarantees both exist, the first node to hear from both sides is the answer.

Why it is fast

Each node is visited at most once and does two comparisons, so O(n) time, and the shortcut stops below targets. Nothing is stored except the recursion stack, O(h). In a binary search tree you can do better: compare the two targets with the node's value and walk down one side, O(h) time with no recursion at all.

How to recognise it in an interview

"Lowest common ancestor", "nearest shared parent", "the node where the paths to p and q split", also "the smallest subtree containing all the deepest leaves". Say: "Each subtree reports whether it holds p or q; the first node hearing from both sides is the LCA." Lowest Common Ancestor of a Binary Tree is the direct form. Lowest Common Ancestor of a Binary Search Tree replaces the reports with value comparisons. Lowest Common Ancestor of a Binary Tree III gives parent pointers, which turns it into walking two chains upward to their meeting point.
