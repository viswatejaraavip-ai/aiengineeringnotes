Start with what you would do by hand

Three workers, three jobs, and a cost table. Each worker takes exactly one job. Which assignment is cheapest?

worker 0worker 1worker 2
job 0927
job 1643
job 2581

By hand you would list the orders: job 0 to worker 0, job 1 to worker 1, job 2 to worker 2; then job 0 to worker 0, job 1 to worker 2, job 2 to worker 1; and so on. For 3 workers there are 3 × 2 × 1 = 6 orders. For 10 workers there are 3,628,800, and for 20 there are about 2.4 × 1018. Orders explode because they remember who got which job in which sequence, which is more than needed.

Build the structure, one piece at a time

What actually matters after placing some jobs is only which workers are already busy, not the order in which they became busy. Record that as a row of bits, one per worker: 1 for busy, 0 for free. With three workers the row is three bits, written as a binary number called a mask. 000 means nobody is busy, 101 means workers 0 and 2 are busy. There are 23 = 8 masks.

The number of 1 bits in the mask (its popcount) tells you how many jobs are already placed, so the next job to place is job number popcount(mask). Keep one number per mask: dp[mask] = cheapest cost of placing the first popcount(mask) jobs on exactly the workers in mask. Fill masks in increasing order; each mask is reached by adding one worker to a smaller mask.

  1. dp[000] = 0: nothing placed, nothing paid.
  2. One bit set, job 0 placed: dp[001] = 9 (worker 0), dp[010] = 2 (worker 1), dp[100] = 7 (worker 2).
  3. Two bits set, job 1 placed on the newest worker: dp[011] = min(dp[010] + 6, dp[001] + 4) = 8; dp[110] = min(dp[100] + 4, dp[010] + 3) = 5; dp[101] = min(dp[100] + 6, dp[001] + 3) = 12.
  4. All three bits, job 2: dp[111] = min(dp[110] + 5, dp[101] + 8, dp[011] + 1) = min(10, 20, 9) = 9.

Cheapest total: 9, with job 0 on worker 1, job 1 on worker 2, job 2 on worker 0.

Why it is correct

The invariant: dp[mask] is the true cheapest way to place the first popcount(mask) jobs on exactly the workers in mask. Any such placement gave the latest job to some worker w in mask; removing w leaves a valid placement of the earlier jobs on mask without w, whose cost is at least dp[mask − w] by the invariant. So the best for mask is the minimum over w in mask of dp[mask without w] + cost of the latest job on w, which is exactly what the loop computes. Order among the earlier jobs never matters, because the cost is a sum.

dp[mask] = min over bits w in mask of ( dp[mask ⊕ 2w] + cost[popcount(mask) − 1][w] )

Why it is fast

There are 2n masks and each looks at up to n bits, so the work is O(2n · n). For 20 workers that is about 21 million steps, against 2.4 × 1018 orders. The gain comes from collapsing every order with the same set of busy workers into one table cell. Memory is 2n numbers, which is why this pattern appears only when n is about 20 or less.

How to recognise it in an interview

Cues: a small n (at most about 20), "every item exactly once", "visit all", "assign", or subsets. Say: the state is the set of items used, which fits in an integer of n bits. Shortest Path Visiting All Nodes stores (mask of visited nodes, current node). Partition to K Equal Sum Subsets asks, for each mask of used numbers, whether the current bucket can be filled. Parallel Courses II uses the mask of finished courses and adds up to k courses per step.
