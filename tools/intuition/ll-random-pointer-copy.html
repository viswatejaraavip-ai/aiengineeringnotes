Start with what you would do by hand

A linked list where each box has two arrows: next, which goes to the following box as usual, and random, which can point to any box in the list or to nothing. Three boxes: 7, 13, 11. next arrows: 7 → 13 → 11. random arrows: 7 → nothing, 13 → 7, 11 → 11 (itself). Make an exact copy: new boxes, same values, same shape of arrows, sharing no box with the original.

By hand, copying the values and the next arrows is easy: walk the list and build 7′ → 13′ → 11′. The random arrows are the problem. The original 13 points at 7; the copy 13′ must point at 7′, not at the original 7. When you reach 13′, how do you find 7′? You could search the new list for the box whose original was 7, but that search walks the list every time: n boxes, each with a walk of up to n, so n2 work.

What you need is a lookup: given an original box, find its copy instantly. That is what a map (a dictionary) is for.

Build the structure, one piece at a time

Piece 1: a map from original to copy. A map stores pairs (key, value) and answers "what is the value for this key" in constant time. The keys are original boxes, the values are their copies.

Piece 2: pass one, create copies. Walk the original list. For each box, create a copy with the same value and no arrows yet, and record map[original] = copy.

The result is 7′ → 13′ → 11′ with randoms nothing, 7′, 11′: the same picture, drawn entirely in new boxes.

A variant without the map. Interleave: after each original box insert its copy (7 → 7′ → 13 → 13′ → 11 → 11′). Now the copy of any box x is x.next, which plays the role of the map. Set each copy's random to original.random.next, then unweave the two lists. Same idea, O(1) extra memory.

Why it is correct

The invariant after pass one: every original box has exactly one copy, with the same value, and the map finds it.

Pass two then sets each arrow of each copy to the copy of whatever the original arrow pointed to. So for every arrow in the original there is a matching arrow between the corresponding copies, and no other arrows. That is the definition of an identical structure. Nothing in the copy points into the original because every target is looked up in the map, which only contains copies.

for every box x: copy(x).next = copy(x.next) and copy(x).random = copy(x.random)

The two passes must be separate: during pass one, a random arrow may point forward to a box whose copy does not exist yet, so arrows can only be wired once every copy exists. The same two-pass shape clones a graph, except that a graph is walked by DFS or BFS and the map doubles as the visited set.

Why it is fast

Two walks over n boxes, with constant work per box because each map lookup is constant time.

time = O(n), memory = O(n) for the map (O(1) extra with interleaving)

Versus n2 for searching the new list on every random arrow.

How to recognise it in an interview

The cues are "deep copy", "clone", "random pointer", "copy a graph", or any structure with cross-references that must be duplicated without sharing. Say: "First pass creates every copy and maps original to copy; second pass wires each copy's pointers through the map."

Copy List with Random Pointer is the example above. Clone Graph is the same map, filled while traversing: when you meet a neighbour not yet in the map, create its copy and recurse; the map also prevents visiting a node twice.
