Start with what you would do by hand

A grid of oranges: 2 means rotten, 1 fresh, 0 empty. Each minute every rotten orange rots its fresh neighbours (up, down, left, right). How many minutes until no fresh orange remains? Grid: row 0 is 2 1 1, row 1 is 1 1 0, row 2 is 0 1 1. By hand you redraw the grid minute by minute: after minute 1 the two neighbours of the rotten one are rotten, after minute 2 two more, and so on until minute 4 when the last one in the bottom right goes.

Redrawing the whole grid each minute costs the grid size per minute, and the number of minutes can be as large as the grid, so about (m × n)2 steps in the worst case. Also, if several oranges start rotten, you must spread from all of them at the same time; handling one source at a time and taking the minimum per cell works but repeats the whole spread once per source.

Build the structure, one piece at a time

Piece one: a queue of (cell, minute) pairs, and a way to mark a cell as rotten so that it is never processed twice. Writing 2 into the grid is the mark.

Piece two: seed the queue with every rotten orange at minute 0, all at once. This is the whole trick. A queue served from the front processes all minute-0 cells, then all minute-1 cells, and so on, so the spread from all sources advances in lockstep, exactly like the redrawing.

Piece three: pop a cell; for each fresh neighbour, mark it rotten and push it with minute + 1. Remember the largest minute pushed. At the end, if any fresh orange is still fresh, the answer is −1; otherwise it is the largest minute.

Why it is correct

Think of all the sources as connected to one imaginary super-source by zero-length edges. Breadth-first search from the super-source then gives every cell its distance to the nearest source, because BFS on an unweighted graph finds shortest distances. Seeding the queue with all sources at minute 0 is exactly BFS from the super-source with the first step already taken.

minute(cell) = min over sources s of distance(s, cell), and the answer = max over cells of minute(cell)

The invariant that makes the queue work: cells are popped in non-decreasing minute order, and all cells of minute d are popped before any of minute d + 1, because pushes always go to the back with a minute one larger than the front. So the first time a cell is marked, it is from a cell at the smallest possible minute, and the recorded minute is the true one.

Why it is fast

Each cell is pushed and popped at most once, with four neighbour checks: O(m × n). Redrawing per minute was up to quadratic in the grid size, and running one BFS per source would multiply by the number of sources. Memory is the queue, at most the grid size.

How to recognise it in an interview

"Spreads each minute from several starting points", "distance to the nearest 0 for every cell", "fill each empty room with the distance to its nearest gate", "how far from land is the farthest water". Say: "I will seed a BFS queue with all sources at distance 0; the first visit of each cell is its distance to the nearest source." Rotting Oranges is this exactly. 01 Matrix seeds with every 0 and writes the distance into each 1. Walls and Gates seeds with every gate. Shortest Distance from All Buildings is the exception that needs one BFS per building, because it wants the sum of distances, not the minimum.
